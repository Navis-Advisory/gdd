# Workflow: tour

This tour reads product documentation only; no engagement access or root selection is needed.

Read-only. Open with exactly: "This is a read-only tour of the main GDD
commands. It will not change your files."

Walk these stages in order, each with: what the command does, the
artifact it writes, and a 2-line format sketch using placeholders such as
{TARGET}, {SEGMENT} and {SOURCE_ID}. Do not introduce a named example engagement:

1. **Scope** (`/gdd:scope-deal`) — the scoping interview; show a 3-line
   ENGAGEMENT.md sketch and one locked taxonomy field with a boundary
   case ("{EXCLUDED_SEGMENT}: OUT").
2. **Decompose** (`/gdd:hypothesis-tree`) — what-must-be-true tree; show
   one branch down to a falsifiable leaf.
3. **Plan** (`/gdd:workplan`) — modules × weeks; one dependency example.
4. **Execute** (`/gdd:size-market`, `/gdd:map-competitors`,
   `/gdd:probe-customers`, `/gdd:assess-moat`, `/gdd:scan-risks`) —
   explain the two-independent-legs rule and why the sizers never see
   each other's work; show a toy reconciliation (e.g. TD $1.2B vs BU
   $1.0B → 20%, within ±30%, gap driver named). Then show each remaining module's output format:
   competitive positioning, customer purchase criteria, a moat kill-test,
   and a risk-screen verdict with its evidence-of-search field. Use
   placeholders rather than invented findings or source claims.
5. **Verify** (`/gdd:triangulate`) — the D1–D8 registry; state the honest
   claim verbatim: consistency and traceability, not truth.
6. **Attack** (`/gdd:red-team`) — kills go CONTESTED, never deleted.
7. **Tell** (`/gdd:storyline`) — governing thought, key line, trace map.
8. **Continuity** (`/gdd:pause-work` / `/gdd:resume-work`) — state
   survives sessions in `.diligence/`.

Close with: the startup ladder, and the posture line — "GDD is a scalpel,
not an autopilot: trust the execution, verify like an engagement
manager."

Never create files, never run analyses, never search the web during the
tour.
